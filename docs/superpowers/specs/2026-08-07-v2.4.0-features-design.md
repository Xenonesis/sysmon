# SysMon v2.4.0 — Feature Expansion Design

Date: 2026-08-07
Status: Approved (design sections reviewed) — pending spec review
Version target: 2.4.0

## Context

SysMon is a Rust/egui Windows system monitor, distributed installer-only via GitHub Releases (v2.3.0 live). `main.rs` is 5191 lines; domain modules exist for updater, startup, privilege.

**Discovery during brainstorming:** the README "Future Enhancements" list was stale — tray icon (menu, tooltip, minimize-to-tray, single-instance), disk I/O rates + history graph, CSV/JSON snapshot export, and Windows alert notifications are all already implemented. Code signing is the only genuinely missing roadmap item (certificate + CI infra, not an app feature).

**User intent:** "more features", prioritization delegated. Selected the Mix scope: top-value feature picks in one release.

## Goals

1. **Process Pro** — search/filter, details panel, kill tree, CPU sort in the Processes tab.
2. **Tray quick actions** — Clean RAM Now, Open Process Manager, Pause Monitoring (checkable).
3. **GPU depth** — per-GPU clock, power draw, fan speed via NVML, graceful when unsupported.
4. **System Info enrichment** — motherboard, BIOS version, GPU driver version, OS build via WMI, lazy-loaded and cached.

## Non-Goals

- Code signing (certificate required; CI/infra task, not app feature)
- Per-process network usage (sysinfo 0.30 limitation)
- AMD/Intel GPU monitoring (NVML-only stays)
- Pause-monitoring persistence (session-only; YAGNI)
- New dependencies (all capabilities available in existing deps: sysinfo, nvml-wrapper, wmi, tray-icon, muda)

## Architecture

```
src/
├── main.rs          (~5191 → ~5400 lines; tray + GPU + system-info changes inline)
├── processes.rs     NEW module (startup.rs pattern: own structs + pure logic)
├── updater.rs       unchanged
├── startup.rs       unchanged
└── privilege.rs     unchanged
```

New module `src/processes.rs` owns process data + pure logic; UI stays in `main.rs` and consumes the module. This keeps `main.rs` from growing further and makes the core logic unit-testable without Windows.

## Components

### 1. `processes.rs` (new)

- `ProcessInfo` + `ProcessDetails` structs (moved from `main.rs`).
  - `ProcessInfo`: existing fields (pid, name, cpu_usage, memory, status).
  - `ProcessDetails`: exe path, command line, cwd, start time, run time, thread count, parent PID, parent name, priority.
- `collect_processes(sys: &System, filter: &str, sort: SortKey, ascending: bool, limit: usize) -> Vec<ProcessInfo>`
  - Filter: case-insensitive substring on name + exe path.
  - Sort keys: Memory (default), CPU, Name, PID; ascending toggle retained.
- `build_process_tree(sys: &System) -> HashMap<u32, Vec<u32>>` — parent PID → child PIDs.
- `kill_order(tree: &HashMap<u32, Vec<u32>>, root_pid: u32) -> Vec<u32>` — deepest-first traversal, cycle-safe via visited set, orphan-safe.
- `lookup_details(sys: &System, pid: u32) -> Option<ProcessDetails>`.
- Actual kill execution stays in `main.rs` (Windows-only, admin-dependent).

UI (`show_processes_tab`): search box in the action bar, sort selector, row click → inline details panel below the table (no modal), kill-tree button per row.

### 2. Tray quick actions (main.rs)

- Menu becomes: `Show Dashboard` | `Clean RAM Now` | `Open Process Manager` | `Pause Monitoring` (checkable) | separator | `Quit`.
- Manual RAM-clean spawn currently inline in `show_ram_cleaner_tab` (lines ~4038-4067) → refactored to `fn start_ram_clean(&mut self, ctx: &egui::Context)`; both the tab button and the tray item call it.
- New field `monitoring_paused: bool` (session-only, not persisted).
- Event handling: existing `MenuEvent::receiver().try_recv()` poll (line ~1929) extended with new ids: `tray_menu_clean_id`, `tray_menu_procman_id`, `tray_menu_pause_id`.
- `Open Process Manager` → `show_process_manager = true` + window shown.
- `Pause Monitoring`: checkable `MenuItem` reflects state; toggle flips `monitoring_paused`.

### 3. GPU depth (main.rs, `get_gpu_info`)

- `GpuInfo` gains `clock_mhz: Option<u32>`, `power_watts: Option<f32>`, `fan_percent: Option<u32>`.
- NVML: `clock_info(Graphics)`, `power_usage()` (mW → W), `fan_speed()`; any error → `None`.
- UI: Overview GPU card + Performance GPU section show `Clock · Power · Fan` when present; `None` fields hidden entirely.
- WMI fallback path: fields stay `None` (no live clocks from WMI).

### 4. System Info enrichment (main.rs)

- One WMI connection, queries: `Win32_BaseBoard` (Manufacturer, Product), `Win32_BIOS` (SMBIOSBIOSVersion), `Win32_VideoController` (DriverVersion), `Win32_OperatingSystem` (BuildNumber).
- Fetched lazily on first System Info tab open, cached in `SystemInfo` struct — no WMI overhead at startup.
- Failure/empty → `None` / "N/A" in UI.

## Data Flow

- **Monitor loop** (existing thread-pool refresh, ~lines 1450-1705): `collect_processes` called with current filter/sort — filtering happens off the UI thread. When `monitoring_paused`, the refresh is skipped entirely; `data` (`Arc<Mutex>`) retains last values; tray tooltip shows `⏸ PAUSED — CPU x% | RAM y%`; the hidden-window refresh path is skipped too.
- **Tray events** are polled in the existing update loop — no new thread.
- **RAM clean**: tray/button → `start_ram_clean(ctx)` → 8 MB-stack worker thread (existing pattern) → `clean_ram()` → `data.ram_clean_freed_bytes` update → `request_repaint()`; success/alert sound + notification reused.
- **GPU**: same `Nvml` instance already held; three extra samples per refresh cycle.
- **WMI system info**: lazy, once, cached.

## Error Handling

| Path | Failure | Behavior |
|---|---|---|
| NVML clock/power/fan | NotSupported / error | `None`; UI hides field; GPU monitoring unaffected |
| WMI queries | fail / empty | `None` / "N/A"; no crash |
| Kill tree | partial access-denied | summary notification "killed 3/5, 2 Access Denied" with failed PIDs |
| Tray build | fail | existing: `tray_icon = None`, menu events skipped |
| Pause + hidden refresh | — | no-op; stale-by-design |

## Testing

**Unit tests (`processes.rs`, pure — run in CI without Windows):**
- Filter: case-insensitive, name + exe path matching.
- Sort: memory desc (default), CPU desc, name asc, PID; ascending toggle.
- `build_process_tree`: parent→children mapping, root-only and childless cases.
- `kill_order`: deepest-first, cycle-safe (visited set), orphan-safe (root not in tree → `[root]`).

**Manual smoke (release build, Windows):**
- Tray: all 4 actions work; pause shows checkmark + PAUSED tooltip; clean RAM reports freed bytes.
- Processes: search filters live; details panel correct; kill tree kills children first (admin).
- GPU: clock/power/fan visible or cleanly hidden.
- System Info: motherboard/BIOS/driver/build populated or N/A.

## Delivery

- Version bump to `2.4.0` in `Cargo.toml` (single source of truth; installer.iss reads `CARGO_PKG_VERSION`).
- CI, updater, installer untouched — existing pipeline builds `setup.exe`, updater compares versions.
- README: add new features; remove shipped items still listed (tray, disk I/O, export).
- Website `docs/index.html`: audit feature cards; update stale ones; `script.js` untouched (release resolution is version-agnostic).
- Tag `v2.4.0` → CI release (same flow as v2.3.0).

## Risks

- `main.rs` bloat — mitigated by `processes.rs` extraction (targeted improvement; no unrelated refactor).
- NVML NotSupported on some GPUs — `Option` fields, UI hides cleanly.
- WMI query cost — lazy + cached.
- Kill tree partial failures — summary notification, never silent.
