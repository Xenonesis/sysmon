# Windows Installer Design (Inno Setup)

**Date:** 2026-08-07
**Status:** Approved by user
**Version:** applies to system-monitor 2.2.0+

## Context

The app currently ships as a portable `.exe` (raw build artifact on GitHub
Releases). Windows search does not find it, there is no Start Menu entry, and
there is no uninstall path. The user wants a normal Windows install experience:
install to Program Files, searchable Start Menu entry, uninstallable from
Settings → Apps, and an auto-update flow that works for an installed app.

## Decisions

1. **Installer format: Inno Setup (EXE).** Chosen by user. Simple `.iss`
   script, standard consumer installer UX, silent install (`/VERYSILENT
   /SUPPRESSMSGBOXES /NORESTART`) for the built-in updater, automatic
   uninstaller + Add/Remove Programs entry. Not MSI — no Group Policy
   requirement for this consumer app.
2. **Keep `requireAdministrator` manifest.** App already runs elevated, which
   also lets it run the silent installer during updates (Program Files is
   write-protected for non-elevated processes). Per-operation UAC refactor is
   explicitly out of scope.
3. **Keep portable exe as a secondary release asset.** Existing portable users
   and the website download link keep working.
4. **Settings are already install-safe.** `AppSettings::load/save` writes to
   `%APPDATA%\Xenonesis\SystemMonitor\settings.json` via the `directories`
   crate — no data lives next to the exe, so Program Files install is safe.
5. **Single version source.** `Cargo.toml` (`CARGO_PKG_VERSION`). CI passes it
   to ISCC as `/DAppVersion` from the git tag.
6. **Fixed AppId GUID** so future versions install over the previous install
   instead of creating a second entry: `{3F2A9C41-8E7D-4B6A-9C21-5D8E4F1A7B62}`.

## Architecture

Three changes, one new file:

- `installer/installer.iss` — Inno Setup script (new)
- `.github/workflows/windows-release.yml` — compile installer + publish asset
- `src/updater.rs` — prefer installer asset; silent-install when app is installed
- `README.md` — install instructions point at the installer

## Installer script (`installer/installer.iss`)

Key directives:

- `AppName=System Monitor`
- `AppVersion={#AppVersion}` (passed from CI via `/DAppVersion=`)
- `AppId={{3F2A9C41-8E7D-4B6A-9C21-5D8E4F1A7B62}`
- `DefaultDirName={autopf}\System Monitor`
- `PrivilegesRequired=admin`
- `OutputBaseFilename=SystemMonitor-{#AppVersion}-setup`
- `Compression=lzma2`, `SolidCompression=yes`
- `SetupIconFile` and `UninstallDisplayIcon` from `assets/icon.ico`
  (generate `.ico` in CI alongside the build; build.rs already converts
  `assets/icon.png` to `.ico`, reuse that path or emit one in the workflow)
- Files section: `system-monitor.exe` only
- Icons section: Start Menu folder entry (makes the app Windows-searchable)
  + optional Desktop shortcut (`Tasks`-gated, default on)
- `[Run]`: "Launch System Monitor" checkbox, `postinstall`, skip silently
  (`/VERYSILENT` runs are no-ops for this step)
- Uninstaller auto-generated by Inno → shows in Settings → Apps

## CI (`windows-release.yml`)

After the existing `cargo build --release` step:

1. Install Inno Setup: `choco install innosetup -y` (or the
   `jrsoftware/innosetup` GitHub Action).
2. Run: `iscc installer\installer.iss /DAppVersion=${{ github.ref_name }}`
   (strip leading `v` from the tag).
3. Upload the resulting `Output\SystemMonitor-*-setup.exe` as a release asset.
4. Keep uploading the portable exe as today.

## Updater (`src/updater.rs`)

**Asset selection** in `check_for_updates`: prefer an asset whose name matches
`*setup*.exe` (installer); fall back to the first `.exe`/`.zip` as today.

**Install path selection** in `download_and_install_update`:

- Detect installed app: `std::env::current_exe()` path contains
  `\Program Files\` (case-insensitive) **or** uninstall registry key exists at
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\System Monitor`.
- **Installed** → if the picked asset is the installer, run it detached with
  `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`, then `std::process::exit(0)`.
  The installer replaces exe, shortcuts, and uninstall entry in one pass.
- **Portable** → existing self-replace PowerShell logic, unchanged.

**Error handling:** silent-install spawn failure returns `Err(String)` — the
existing UI toast path shows the message. No fallback to portable
self-replace when installed (would split install state).

## Docs

- `README.md`: "Installation" section rewritten — primary path is the
  installer (`SystemMonitor-<ver>-setup.exe`); portable exe documented as an
  alternative. Remove stale "Start Menu entry" marketing claim or make it
  truthful (installer creates it).
- Website (`systemmonitor.xenonesis.dev`) is a separate repo — out of scope,
  noted for follow-up.

## Verification

1. `cargo build --release` passes locally and in CI.
2. CI step compiles the installer (`ISCC` exit 0) and uploads both assets.
3. Manual Windows test: run installer → app lands in
   `C:\Program Files\System Monitor`, Start search finds "System Monitor",
   Settings → Apps shows the uninstall entry, uninstall removes everything.
4. Update test: install 2.2.0, then trigger updater with a newer tag →
   silent installer replaces the app without a second uninstall entry.

## Out of scope

- Per-operation UAC elevation refactor (app stays `requireAdministrator`)
- Code signing (no cert available)
- MSI/Group Policy support
- Website changes
